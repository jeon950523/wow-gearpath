# 와우 장비·파밍 경로 도구 — MVP 0.1

한국 리테일 캐릭터의 장착 장비를 진단하고 솔플·구렁 경로를 우선 제시하는 팬 도구입니다. Next.js 웹 화면과 기존 CLI를 제공합니다. [운영 사이트](https://wow-gearpath.kro.kr) · [프로젝트 기준 문서](docs/SSOT.md)

```sh
npm ci
npm run dev
npm test
npm run build
npx playwright install chromium --only-shell
npm run test:e2e
```

로컬 웹은 `http://localhost:3000`에서 열립니다. API 환경변수 없이도 샘플을 볼 수 있습니다. 로컬에서 실조회할 때만 `.env.local`을 사용하세요. Vercel은 Next.js 프리셋, 저장소 루트, Production 환경변수 `BLIZZARD_CLIENT_ID` 및 `BLIZZARD_CLIENT_SECRET`을 사용합니다. 실제 검증 상태는 [TASK-002 보고서](docs/reports/TASK-002-REPORT.md)에 기록합니다.

## 바로 보기

[샘플 보고서](sample-report.html)를 브라우저에서 열면 설치 없이 결과를 볼 수 있습니다. 샘플 캐릭터·장비·강화 수치는 가상입니다.

기존 CLI는 Node.js 22 이상에서 사용할 수 있습니다. 아래 명령은 이 프로젝트 폴더에서 사용합니다.

```powershell
npm test
npm run demo
npm run diagnose -- examples/manual-template.json
npm run live -- azshara 캐릭터명
```

`demo`는 2026-11-26 10:00 KST로 분석 시각을 고정해 재현합니다. `diagnose`와 `live`는 현재 시각을 사용합니다. 수동 입력의 `observedAt`은 실제 확인 시각으로 바꾸세요. 규칙은 2026-12-03 00:00 KST까지 검토 유효하며, 이후에는 재검증 없이 시즌 추천을 내지 않습니다. 이 날짜는 시즌 종료일이 아닙니다.

CLI 실조회는 같은 환경변수를 사용합니다. CLI는 파일을 자동으로 읽지 않으므로 필요한 경우 Node의 `--env-file`을 사용하세요. 웹 서버의 실조회는 Vercel Production 변수로 별도 확인합니다.

## 구현된 범위

- 한국 캐릭터 장비 JSON 입력, 필수 필드·중복 슬롯·잘못된 수량 검증.
- 16개 장착 슬롯 기준 평균, 양손 무기 2슬롯 가중치, 낮은 슬롯 5개 진단. 빈 슬롯·무기 방식 미확인 시 평균 판정 보류.
- 솔플·구렁 우선 경로와 열쇠 보유 여부 분기. 미입력은 0개와 구분.
- **반올림 전 장착 평균 315 이상에서만** 레이드·쐐기 후보 추가. 이는 사용자가 정한 정책이며 공식 입장·모집 기준이 아닙니다.
- 출처와 관측 시각을 포함한 보유 재화·열쇠·구렁 해금 정보, 보유 쐐기 던전/단계 수동 입력.
- 공식 공지에 따른 11단 풍요로운 구렁의 승천의 맹독석 조건부 후보.
- 데모 전용 강화 단계 비교: 하나의 공유 재화·골드 예산에서 차감. 단계별 탐욕 방식이며 전체 최적해가 아닙니다.
- OAuth 서버 인증 및 KR 장비 조회 어댑터. 가짜 응답으로만 검증했으며 실응답 계약 검증은 남아 있습니다.
- 외부 업로드 없는 로컬 HTML 보고서. 실제 캐릭터 결과는 기본 `private/`에 저장합니다.

## 데이터 검증 결과

2026-11-26 기준 한국어 공식 공지에서 한밤 2시즌과 12.1.5를 확인했습니다. 세부 근거·접근 실패·검증 등급은 [데이터 출처](docs/data-sources.md)에 기록했습니다.

| 항목 | 현재 처리 |
| --- | --- |
| 캐릭터·장착 슬롯·아이템 인스턴스 레벨 | Blizzard 공개 프로필/장비 API 연결 코드, 실조회 미검증 |
| 장비 강화 트랙·단계 | 입력값 사용; 아이템 레벨·아이템 ID로 역추정하지 않음 |
| 보유 열쇠·문장·골드·맹독석 | 수동/애드온 JSON 입력; 공개 API로 보유량을 얻는다고 가정하지 않음 |
| 보유 신화 쐐기돌 | 수동/애드온 입력; 최고 완료 기록과 구별 |
| 금고 이번 주 진행·보상 후보 | 게임에서 확인하도록 안내; 자동 조회 미구현 |
| 현재 시즌 단계별 보상·강화표 | 공식 검증 대기, 실사용 소비 계산 비활성 |
| 애드온 | 내보내기 데이터 계약과 JSON 입력 지원; 게임 내 수집 애드온은 아직 없음 |

API 키는 사용자 로그인과 다릅니다. 공개 캐릭터 조회에는 앱 인증을 사용하도록 설계했으며, 계정 캐릭터 목록·보호 프로필은 사용자 동의 기반 인증이 필요한 별도 범위로 남겼습니다. 개발자 문서 본문 접근 실패 때문에 최신 지원 필드 및 인증 조건은 실연동 전 다시 확인해야 합니다.

## 수동 / 애드온 입력

`examples/manual-template.json`은 입력 형식 예제이며 실제 캐릭터가 아닙니다. 각 장비의 `slot`, `itemId`, `ilvl`, `track`, `rank`를 수정하세요. 모르는 트랙·단계는 `null`로 둡니다. `weaponMode`는 `two-hand`, `dual-wield`, `one-hand`, `unknown` 중 하나입니다. `one-hand`에는 방패·보조장비가 있는 형태를 포함하며, 평균 계산에는 두 무기 슬롯이 필요합니다.

재화는 `resources`의 임의 키에 `{value, source, observedAt}`로 입력합니다. `cofferKey`는 복원된 금고 열쇠, `gold`는 골드 단위 정수, 나머지는 입력자가 식별한 시즌 재화 키입니다. `value: null`은 미확인입니다. 열쇠 조각은 `cofferKeyShard`처럼 별도 보관하며 자동 교환하지 않습니다. 실서비스에서는 표시 이름 대신 시즌별 공식 재화 ID 사전을 검증해 연결할 예정입니다.

`progress`는 구렁 최고 해금 단계 `maxDelveTier`와 맹독석 해금 여부 `venomstoneUnlocked`를 받습니다. 최고 해금 단계가 현재 안정적으로 완료할 수 있는 단계라는 가정은 하지 않습니다. `keystone`은 선택 항목이며 `{dungeon, level, source, observedAt}` 형식입니다.

출처는 `manual`, `addon`, `blizzard`, `sample` 중 하나입니다. 모두 검증된 진위 인증이 아닌 입력 provenance 표기입니다. 자동 애드온 수집, API와 애드온의 충돌 병합, 서명 검증은 구현하지 않았습니다. 애드온 사용 시 이 JSON 계약에 맞춰 내보내도록 만들며 Lua/SavedVariables 파일을 실행하지 않습니다. 다른 캐릭터의 자료가 섞이지 않도록 최상위 캐릭터 식별자를 대조해야 합니다.

## 다음 구현 순서

1. 공식 개발자 콘솔과 실제 KR 캐릭터 응답으로 스키마·인증·동기화 시각을 확인합니다.
2. 게임 내 강화 창/보상 화면과 공식 업데이트 문서를 대조해 시즌별 트랙·랭크·할인·특수 강화를 검증합니다.
3. 애드온으로 보유 재화·열쇠·보상 상태를 내보내고, 아이템 인스턴스 식별자로 API 자료와 병합합니다.
4. 검증된 표를 바탕으로 지금 얻는 보상과 다음 주 금고, 교체 확률, 완료 시간 추정치를 분리해 비교합니다.
5. 캐릭터 조회·입력 수정·계획 비교가 가능한 웹 화면을 추가합니다.

전체 구조와 MVP 수용 조건은 [설계](docs/mvp-design.md)를 참고하세요.
