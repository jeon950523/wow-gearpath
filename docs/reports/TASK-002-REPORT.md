# TASK-002 검수 보고서

## 최초 검수

- 배포 문제: 운영 도메인은 Vercel의 404 NOT_FOUND를 반환했습니다. 기존 저장소에는 브라우저용 시작 화면이나 API 라우트가 없었습니다.
- 기능 개선 대상: 서버 선택, 직업/전문화/아이템 등급·아이콘, 쌍수 양손 무기 처리, 입력 진행 정보, 오류별 안내.
- 효율 개선 대상: 동시 OAuth 발급, 중복 프로필·서버·아이콘 조회. 인스턴스별 제한 크기의 TTL 캐시를 추가했습니다.
- 기존 정상 동작: CLI, 슬롯 가중치, 315 비교, 미입력/0 구분, 공유 재화 차감과 미검증 시즌 보호. 동일한 엔진을 웹에서 사용합니다.
- 환경 변수는 서버 전용 모듈에서만 읽습니다. `.env` 계열과 플랫폼 생성 파일은 Git에서 제외됩니다.

## 검증

- 단위 테스트는 기존 추천·입력 시나리오와 KR 요청 가짜 응답, 토큰 공유와 재발급, 아이콘 허용 호스트 및 비밀값 없는 반환을 검증합니다.
- 브라우저 E2E의 캐릭터 데이터는 가짜 응답입니다. 일부 요청은 로컬 Production 서버 라우트를 직접 호출합니다.
- 로컬 단위 테스트 33개와 Next.js Production 빌드를 통과했습니다.
- 운영 반영 및 실데이터는 배포 이후 별도 확인 대상입니다.

## 운영 확인 절차

1. 운영 도메인에서 `/`와 `/api/realms`의 HTTP 응답 및 화면을 확인합니다.
2. 정상 KR 캐릭터를 선택하고 `/api/character`의 캐릭터명·서버·장비 슬롯·레벨이 게임과 일치하는지 대조합니다.
3. 없는 캐릭터의 404와 잘못된 입력의 400을 확인합니다. 네트워크 탭에서 Client Secret과 토큰이 없는지 확인합니다.
4. 상세 시즌 수치와 할인 검증, 애드온 내보내기 제작은 다음 작업으로 진행합니다.
