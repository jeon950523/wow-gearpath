# MVP 설계

## 목표와 판단 기준

지금 가진 장비·열쇠·재화로 다음에 무엇을 확인하고 어디를 도는지 설명합니다. 기본은 솔플과 구렁입니다. 장착 평균이 315 이상이면 그룹 콘텐츠도 후보에 추가합니다. 낮은 장비 슬롯은 교체 우선 점검 대상이며, 낮은 아이템 레벨이 항상 전투 성능 병목이라는 뜻은 아닙니다.

0.1은 재현 가능한 진단 파이프라인입니다. 현재 시점의 모든 파밍 경로를 최적화한다는 수용 조건은 적용하지 않습니다. 보상 확률·실패율·이동/대기/완료 시간·직업별 성능 모델이 없으므로 시간당 기대 이득을 수치로 꾸며내지 않습니다.

## 구성

```text
Blizzard 공개 API ─ 어댑터 ─┐
                          ├─ 캐릭터 스냅샷 검증 ─ 진단 엔진 ─ 로컬 HTML
수동/애드온 JSON ───────────┘                         └─ 샘플 JSON 결과
                              시즌 규칙 팩 ─────────┘
```

Node 표준 라이브러리만 사용하고 별도 데이터베이스·호스팅·원격 저장소는 만들지 않습니다. API 어댑터와 계산 엔진을 분리해 비밀키 없이 기능을 재현할 수 있습니다. MVP에서는 두 입력 경로를 자동 병합하지 않습니다. 애드온 출력은 동일한 스냅샷 계약을 사용합니다.

## 입력 계약

- 식별: schemaVersion, region=kr, realm slug, name, seasonId, source, observedAt.
- 장비: slot, itemId, ilvl, 선택적 name/track/rank. 강화 상태는 아이템 인스턴스 단위로 다뤄야 하며 아이템 ID만으로 결정하지 않습니다.
- 무기: weaponMode. 양손은 2슬롯 반영. 보조장비 충돌·누락·미확인 모드는 판정 보류. 쌍수 양손 등 특수 구성은 현재 명시적 두 슬롯을 가진 dual-wield로 입력하고 실게임 평균과 검증해야 합니다.
- 재화: 이름 키별 value, source, observedAt. 0과 null을 구별. 이후 실제 시즌 재화 ID 매핑 필요.
- 진행: 구렁 해금 단계, 맹독석 퀘스트 해금 여부, 출처/시각. 실제 완료 가능 단계 및 주간 금고 상태는 추가 수집 대상.
- 쐐기: 던전, 단계, 출처, 시각. 과거 최고 완료 기록과 보유 키를 혼동하지 않음.

형식은 `examples/manual-template.json`과 `examples/sample.json`에 있습니다. 수동 자료의 진실성·동일 캐릭터 여부는 앱이 증명하지 않습니다. 프로필 소유권 검증은 향후 사용자 로그인 도입 범위입니다.

## 추천 정책

장비 16슬롯 가중 평균의 원시 값을 기준으로 315를 비교합니다. 표시 반올림값과 가방 포함 평균은 판정에 사용하지 않습니다. 장비가 24시간 이상 지났거나 과도한 미래 시각이면 그룹·소비 추천을 중단합니다. 재화는 개별 시각으로 검증합니다. 이 24시간은 제품 정책이며 Blizzard 갱신 주기가 아닙니다.

현재 엔진은 낮은 슬롯 → 안전하게 완료할 구렁 확인 → 열쇠 상태별 안내 → 금고 진행 확인 순서로 반환합니다. 11단 해금·맹독석 해금·열쇠 보유가 함께 있을 때만 해당 구렁을 추가 후보로 제시합니다. 보상 횟수·드롭 수량·성공을 보장하지 않습니다. 그룹 후보는 315 조건 외에도 숙련도·역할·모집 조건을 확인하도록 합니다.

검증된 강화표가 없으면 재화 소비 추천을 비웁니다. 데모는 다음 1단계의 평균 증가/문장 비용이 높은 후보를 반복 선택하고 공유 지갑을 차감합니다. 골드 부족, 단계 상한, 트랙/레벨 불일치, 불완전 장비에서는 소비를 막습니다. 탐욕 방식은 전체 예산의 최적 배분이나 특정 목표 도달 최소 비용을 보장하지 않습니다.

## 향후 실제 효율 모델

각 후보에 즉시/주간 보상, 고정/무작위 획득, 슬롯 적합성, 고유 장착·세트 효과, 현재·최대 강화 레벨, 문장/골드 비용, 열쇠 소비, 반복 제한, 성공 가능성 및 시간 추정의 근거를 넣습니다. 사용자가 완료 가능한 단계와 시간 예산을 입력하면 기대 슬롯 개선/시간과 확정 강화 이득을 따로 보여줍니다. 서로 다른 문장을 임의의 동일 가치로 합산하지 않습니다.

드롭률이 없으면 정확한 기대값 대신 가능한 레벨 범위·미확인 확률을 표시합니다. 금고 후보를 여러 개 해제해도 수령 아이템 수와 동일하다고 계산하지 않습니다. 이미 받은 주간 보상·촉매/제작 제한·교환 성취·전투부대 할인·추가 강화는 각각 별도 조건으로 모델링합니다.

## 완료된 검증과 남은 검증

자동 테스트는 315 경계, 무기 가중치, 불완전 장비, 시즌/시각, 공유 예산, 잘못된 입력, 출력 escape, OAuth/URL/오류 처리를 검사합니다. `npm test`로 재실행할 수 있습니다. 샘플 보고서는 `npm run demo`로 재생성합니다.

실제 Blizzard 인증·캐릭터 응답, 게임 내 평균/장비 대조, 강화/보상 전수 표, 애드온 게임 실행, 브라우저 화면의 시각 QA는 아직 수행하지 않았습니다. 보고서는 로컬 파일이며 웹 앱 로그인·입력 편집 UI는 다음 단계입니다.
