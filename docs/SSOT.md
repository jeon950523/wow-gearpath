# WoW GearPath 기준 문서

- 한밤 시즌 팩은 `src/data/expansions/midnight/season-2/`에 둡니다. 재검토 일자는 공식 시즌 종료일과 별도로 관리합니다. 검증된 규칙만 운영 판정에 사용합니다.
- [ADDON-003B 전달 계약](contracts/ADDON-003B-HANDOFF.md)에 신규 수신 키와 한국 클라이언트 검증 상태를 기록합니다. 전투부대 잔액은 캐릭터끼리 합산하지 않습니다.

- 웹 저장소의 [계약 v1](../contracts/snapshot-v1.schema.json)이 애드온 JSON의 정본입니다. [버전 기록](../contracts/CHANGELOG.md) · [로드맵](ROADMAP.md)
- 애드온 스냅샷은 브라우저 메모리에서 검증하고 장비 세트와 재화의 출처 및 시각을 유지합니다.

- 대상은 한국 리테일입니다. 장착 평균 315 이상에서 레이드와 쐐기 후보를 추가합니다.
- Next.js App Router와 TypeScript가 웹 입력과 서버 요청을 처리합니다. 추천은 웹과 CLI가 같은 JavaScript 엔진을 사용합니다.
- Blizzard OAuth 자격증명은 Vercel Production 서버에만 두고 공개 캐릭터 및 게임 데이터 API에 사용합니다.
- 장착 평균은 반올림 전 값을 비교합니다. 누락 장비나 무기 유형 미확인 시 판정을 보류합니다.
- `src/rules.mjs`가 시즌과 규칙의 출처·확인 상태를 관리합니다. 확인 자료는 [데이터 출처](data-sources.md)에 기록합니다.
- 보유량의 `null`은 미입력입니다. 수동 입력은 브라우저 메모리에서 처리하고 최근 검색만 해당 브라우저에 저장합니다.
- 제출 기준은 직접 단위·교차 테스트, Production 빌드 및 헤드리스 E2E입니다. GitHub Actions는 수동 실행 전용입니다. Vercel 자동 배포는 main에 한합니다.
- 작업 현황과 인계는 [HANDOFF](HANDOFF.md)를 참고합니다.

## SimulationCraft(SimC) 통합 방향 — 2026-11-26 사용자 승인

- 서비스 목표: 아이템 레벨 성장·재화/시간 효율과 전투 성능(DPS 등)을 독립적으로 분석하고 결과를 종합해 개인별 파밍/강화/보존 경로를 추천한다. 템레벨 상승을 DPS 상승으로 추정하지 않는다.
- 기존 오픈소스 [SimulationCraft](https://github.com/simulationcraft/simc) 엔진 활용을 우선 검토한다. 자체 전투 엔진 재구현은 범위 외. 엔진 버전/게임 빌드 지원, 라이선스, 데이터 재배포 및 외부 서비스 이용 조건은 구현 전에 확인한다.
- 기존 공식 API + GearPath 애드온 흐름을 유지한다. 초기에는 기존 SimulationCraft 애드온의 /simc 텍스트를 사용자 입력으로 가져오고, 사용자가 직접 실행한 심크 결과를 가져와 분석한다. Raidbots 자동 제출/비공개 API 접근을 전제로 하지 않는다.
- 결과에는 캐릭터·전문화·장비/특성 구성 식별자, 입력 스냅샷/관측 시각, 게임 패치, 엔진 버전, 시나리오, 전투 시간, 대상 수, 반복 횟수, 오차 및 결과 출처를 보존한다. 조건이 다른 결과는 동등 비교하지 않는다. 미지원/미실행/누락은 0 DPS로 표시하지 않는다.
- 솔플 무버프 단일/다중 대상과 전투 시간별 시나리오를 기본 후보로 삼고, 레이드/쐐기 시나리오를 별도 제공한다. 구렁 실제 환경·생존·탱킹·치유를 DPS만으로 확정하지 않는다. 기존 315 및 솔플 선호 정책 유지.
- 비용 원칙: 초기에는 입력/결과 파싱 및 분석에 집중하고 이후 사용자 PC의 SimC 실행 연동을 우선 검토한다. Vercel/Actions에서 상시 고비용 심크 실행 금지. 서버 운영 및 WASM은 별도 비용/기술/보안 검증과 승인 후 결정한다.
- 사용자 입력은 실행 명령이 아닌 제한된 비신뢰 데이터로 처리한다. 외부 파일 포함/임의 명령 실행/임의 URL 접근 금지, 입력 크기 및 파싱 범위 제한, 개인 데이터 최소화. 실제 SimC 실행 시 별도 샌드박스·시간/메모리/조합 상한 필요.
- 공통 계약 변경 선합의 → 익명 fixture → 양쪽 독립/교차 검증 → 실제 클라이언트/엔진 검증 → 병합. 양쪽 커밋 SHA, SimC 버전, 명령, 결과 및 미검증 범위를 기록하며 GitHub Actions는 수동 예외 검증만 사용한다.
### 웹 책임 및 단계
- SIM-001: 기존 /simc 프로필 텍스트 입력/검증, GearPath JSON 및 API와 안전하게 매칭. 지원하는 SimC 입력 문법의 범위를 정의하고 알 수 없는 지시문은 실행하지 않는다.
- SIM-002: 사용자가 내보낸 실제 SimC/Raidbots 결과의 지원 형식·비교 UI, 기준 DPS 대비 차이·불확실성·장비 레벨을 함께 표시. 외부 서비스 결과 접근/이용 조건 검증 전 자동 연동 금지.
- SIM-003: 사용자 PC의 버전 고정 SimC 실행 연동 검토. 별도 로컬 실행 모듈, 안전한 입력, 취소/시간 제한 및 결과 검증. 서비스 서버의 자동 실행은 승인 범위 외.
- SIM-004: Quick Sim, Top Gear, Droptimizer, Upgrade Sim, 특성·장신구·티어·보석/마법부여 비교. 후보 선별, 조합 상한, 캐시 키(버전/패치/프로필/시나리오), 통계 오차 비교를 먼저 설계한다.
- TASK-009 이후 통합: 실제 시뮬레이션 결과를 재화 기회비용·획득 가능성·시간·주간 제한과 결합한다. 미검증 보상 규칙이나 가상의 DPS를 실제 추천 근거로 사용하지 않는다.
- 현재 TASK-004 시즌/재화 계약과 ADDON-003A 검증을 우선 유지한다. SIM-001/002는 장비/강화 엔진 기반 확보 후, SIM-003/004는 별도 단계로 진행한다. 이 변경은 계획/문서만이며 계약의 실제 신규 필드, 런타임, 배포 기능 및 엔진은 아직 구현하지 않는다.
