# 외부 애드온 활용 및 공통 수집·분석 정책

2026-11-26 KST · 사용자 승인. 이 문서는 두 저장소가 공유하는 개발 원칙과 기능별 참고 후보를 정리한다. 기존 SSOT의 SimulationCraft, 웹/애드온 책임 분리, 계약 선합의, 직접 검증 및 비용 제한 정책을 유지한다. **후보 지정은 코드 반입 승인이나 실제 패치 호환성 확인을 뜻하지 않는다.** 이번 문서 갱신 자체로 외부 코드·DB·이미지를 반입하거나 런타임을 변경하지 않는다.

## 기성 애드온 우선 정책 (2026-11-27)

새 기능을 구현하기 전에 후보의 공개 API, 실제 소스·버전, 대상 패치, 라이선스·제3자 데이터 권리와 관측 범위를 확인한다. 설치 강제나 전체 코드·DB 반입 없이 검증된 기능을 재사용하고 GearPath는 계약·정규화·통합 추천에 집중한다. CraftSim·PSL·Merchant Plus·Enhanced Crafting은 검토 후보이며, CraftSim 참고값은 직접 관측과 분리한다. ## 1. 목표 및 역할 분리

- 검증된 기존 애드온과 공식/공개 WoW API를 먼저 조사하여 같은 수집 문제를 반복 구현하지 않는다. GearPath의 핵심 가치는 데이터 정규화·품질 관리, 장비/실제 전투 성능, 재화·시간 효율, 활동·골드·전투부대의 개인별 통합 성장 추천이다.
- 애드온: 게임 내부의 관측 가능한 값만 비전투·읽기 전용으로 수집하고 정규화된 스냅샷을 내보낸다. 외부 애드온 설치를 일괄 강제하지 않는다. 기존 /simc 입력은 초기 별도 사용자 경로로 유지한다. 다른 애드온의 UI, DB, 타이머, 자동 추적/추천, 라이브러리를 통째로 가져오지 않는다.
- 웹: 공통 계약의 정본, 출처별 병합·검증·시즌 규칙, 성장/재화/콘텐츠/골드/실제 심크 결과 분석 및 통합 추천을 담당한다. 게임 내부 API를 웹에서 직접 호출할 수 있다고 가정하지 않는다. 외부 데이터 및 서비스의 이용·재배포 조건을 별도로 확인한다. 모든 참고 애드온을 웹에 설치하거나 서버에서 실행하는 설계가 아니다.
- 두 저장소는 각각 담당 영역을 유지한다. 데이터 계약 변경은 웹 정본에 정의 → 익명 fixture → 양쪽 독립 구현/검증 → 교차 검증 → 실제 클라이언트/엔진 검증 → 병합 순서로 진행한다.

## 2. 외부 코드·데이터 활용 원칙

1. 기능 구현 전 관련 후보의 현재 업스트림 저장소/커밋, 대상 파일, API 사용 방식, KR 리테일 패치·빌드 호환성, 라이선스 원문 및 제3자 라이브러리/데이터 권리를 검토한다. 동등하게 검증된 기성 기능의 공개 API 어댑터 또는 권리가 확인된 최소 모듈을 우선한다. 적합한 기능이 없거나 계약·범위·시각·권리·안전·비용 문제를 문서화한 경우에만 자체 수집기나 계산 엔진을 확장한다.
2. 허용된 작은 수집 모듈 또는 필요한 로직만 선별해 GearPath 어댑터로 통합한다. UI, 중복 이벤트 등록, 폴링, 저장 DB, 불필요한 의존성, 영어 제목 의존 및 추천 로직은 필요성과 권리가 확인된 경우에만 채택한다.
3. 공개 GitHub는 재사용 허락이 아니다. MIT/Unlicense 등도 실제 파일 및 포함 구성요소의 조건을 확인한다. All Rights Reserved, 불명확한 라이선스, 외부 데이터는 권리자의 명시적 허락 또는 해당 권리 범위가 확인되기 전 코드·데이터 복제/변형/재배포 금지. 허락 전 공개 API 문서와 독립 구현으로 해결한다. 권리자 연락/허락은 사용자가 승인·진행하며 미획득 허락을 완료로 표시하지 않는다.
4. 실제 반입 시 해당 저장소 THIRD_PARTY_NOTICES.md에 프로젝트, 권리자, 원본 URL/SHA, 대상 파일·범위, 라이선스 또는 허락 증적, 변경 내용을 기록한다. 필요한 저작권 및 라이선스 원문은 소스와 배포 ZIP/산출물에 보존한다. 라이선스가 다른 소스/데이터는 분리 검토한다. 업스트림 변경은 차이 및 호환성 검증 후 반영한다.
5. 기존 구현도 정확성, 예외·누락, 보안, 데이터 계약, 가독성, 성능을 시니어 기준 검수한다. 모의 테스트와 실제 게임/웹 검증을 구분하고, 소스 SHA·테스트 명령·결과·미검증 항목을 기록한다. 기능적 개선과 효율적 개선을 별도 보고한다. GitHub Actions는 기존 수동 예외 정책을 유지한다.

## 3. 공통 수집 계층 설계 기준

- 개별 기능은 도메인별 어댑터(퀘스트, 보상, 장비, 재화, 구렁, 금고, 가방/은행, 부캐 등)로 구분하되 같은 WoW API 호출과 동일 관측값은 가능한 한 공통 수집 계층에서 재사용한다. 실제 코드 구조는 프로파일링과 기존 모듈 검수 후 결정하며 이번 문서에서 신규 모듈 구현을 선언하지 않는다.
- 관측 요청에는 수집 범위, 캐릭터/전투부대 범위, 패치·시즌, 관측 시각, 전문화/전리품 전문화 및 발생 회차 등 필요한 식별자를 사용한다. 다른 캐릭터, 다른 발생 회차, 다른 아이템 인스턴스의 값은 섞지 않는다.
- 중복 API 요청·이벤트 핸들러·지도/가방 전체 반복 순회를 제거한다. 동일 요청에서 조회 결과를 공유하고 필요한 경우에만 제한된 세션 캐시, dirty flag, 이벤트 디바운스, 미준비 데이터의 제한적 재시도를 도입한다. 무제한 폴링, 전투 중 수집/자동화, 과도한 메모리 사용 금지. 캐시 범위/TTL/무효화/상한을 정하고 측정한다.
- 관측값과 캐시값 및 실제 관측 시각을 구분한다. 준비되지 않은 보상/부분 스캔/일시 오류는 검증된 값을 무조건 덮지 않는다. 완료·만료·발생 회차 변경·캐릭터/조건 변경 시 필요한 캐시를 무효화한다. 보상 종류별 수집 상태를 독립 관리하고 실패·미수집·미해금·실제 0을 구분한다. 은행 미접근은 빈 은행, 미발견 퀘스트는 완료, 표시 보상은 실제 획득 보상으로 추정하지 않는다.
- 계약·fixture는 필요한 최소 데이터만 노출한다. 외부 저장 데이터나 다른 애드온의 내부 DB를 신뢰된 값으로 자동 합치지 않는다. 비밀값·계정 식별자·개인 보유량/원본 로그의 저장 및 외부 전송을 최소화한다. 동일 공유 재화 중복 합산 금지.
- 웹은 수집 데이터를 다시 불필요하게 계산/조회하지 않고 출처, 시각, 범위, 검증 상태를 보존해 분석한다. 검증된 시즌 규칙 및 실제 SimC 결과만 실사용 추천에 이용한다. 경매 가격·획득 확률·DPS·골드 기대값을 임의 생성하지 않는다. 입력 변경에 따른 중복 분석 비용은 측정 후 최적화한다.

## 5. 기존 근거 및 유지 방법

- 애드온 조사 기준 브랜치 SHA 448b7c8b752f86852264744dc52d6c762858f06c의 [ADDON-REFERENCES.md](https://github.com/jeon950523/wow-gearpath-addon/blob/448b7c8b752f86852264744dc52d6c762858f06c/docs/research/ADDON-REFERENCES.md), [REUSE-POLICY.md](https://github.com/jeon950523/wow-gearpath-addon/blob/448b7c8b752f86852264744dc52d6c762858f06c/docs/research/REUSE-POLICY.md), [THIRD_PARTY_NOTICES.md](https://github.com/jeon950523/wow-gearpath-addon/blob/448b7c8b752f86852264744dc52d6c762858f06c/THIRD_PARTY_NOTICES.md)를 근거로 삼았다. 해당 브랜치의 상세 조사, 실제 반입 및 검증 기록은 별도로 유지한다. 현재 main에 반입 코드가 있다고 주장하지 않는다.
- 두 저장소의 이 공통 문서와 SSOT 링크를 유지한다. 새로운 후보·권리 변경·반입 결정은 담당 저장소의 상세 조사/고지에 기록하고 양쪽 공통 정책에 필요한 변경을 조율한다. 작업 중인 브랜치는 병합 전 최신 main의 정책을 반영하되 진행 중인 소스/테스트/이력을 덮어쓰지 않는다.
- 신규 후보의 실제 라이선스/패치 호환성 검증, 공통 수집 계층 구현, 코드 반입, 전체 게임/웹 검증은 각 기능 작업의 승인 조건이다. 이 문서 변경 자체에는 런타임 테스트를 요구하지 않으며 정적 문서 및 링크 검수와 실제 실행 검증을 구분한다.
