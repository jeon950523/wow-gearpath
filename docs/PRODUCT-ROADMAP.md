# GearPath 최상위 제품 목표 및 병렬 개발 운영 계획

## 작업 번호 및 순서 관리 (2026-11-26 사용자 승인)
기존 기획의 본 TASK 번호·목적·순서를 고정한다. 중간에 생긴 연동/오류 수정/추가 기능/검수 작업은 해당 본 작업의 TASK-NNN-1, TASK-NNN-2처럼 순차 하위 번호를 부여한다(예: TASK-006-1, TASK-006-2). 이후 본 TASK 번호를 밀거나 기존 이력을 이름 변경하지 않는다. 기존 TASK-003A, TASK-005A 및 독립 CONTRACT/SIM/ADDON 식별자는 보존한다. 필수 선행과 선택 개선을 구분하며 완료 조건에 필요한 하위 작업은 다음 본 TASK 전에 마친다. 하위 번호는 작업지시서·보고서·브랜치·PR·HANDOFF에서 동일하게 사용한다. 상대 저장소의 진행 중 작업을 임의 변경하지 않는다. 기존 공통 로드맵의 단계별 진입 조건을 유지한다.

2026-11-26 KST 사용자 승인. 양쪽 저장소 공통 정책. 기존 SSOT, 데이터 계약, 외부 애드온 재사용 정책, 직접 검증/수동 CI를 보존한다. 우선순위와 단계 진입 판단은 본 문서를 따른다. 기존 작업 ID와 이력은 변경하지 않는다.

## 1. 최상위 목표
한국어 WoW 리테일 전용 종합 성장 관리 Companion App. 장착/보유 장비와 재화·활동·획득처·실측 전투 성능을 근거로 오늘 무엇을 할지, 이번 주 무엇이 남았는지, 어떤 장비를 강화/교체하고 무엇을 보존할지 판단한다. 최종적으로 경량 독립 PC 앱과 웹, 인게임 애드온이 공통 계약/분석을 사용한다. Overwolf 전체 플랫폼 재현은 목표가 아니다. 솔플·구렁 우선 및 기존 315 그룹 콘텐츠 경계 정책은 유지한다. 숫자 및 규칙은 시즌별 검증한다.

PHASE 1/2는 서로 필요한 세로 기능 단위로 병렬 수행한다. 각 기능이 완성되면 수집→계약→웹 화면→실사용 검증까지 연결한다. 데이터 수집 전 범위 완료까지 웹 개발을 멈추지 않으며, 미관측 값으로 빈칸을 허위로 채우지 않는다. SIM-001/002의 프로필/실제 결과 파싱·계약 준비는 핵심 MVP를 방해하지 않는 작은 독립 작업으로 진행 가능하다. 실제 로컬 실행 SIM-003 및 광범위 조합 SIM-004는 후속 단계로 유지한다. PC 저장소 생성, 앱 구현, 프레임워크 확정, 설치 프로그램 제작은 PHASE 2 완료와 사용자 승인 전 금지. Tauri 우선 검토(확정 아님), 기존 React/TS/순수 분석 엔진 재사용 가능성 검증, Next.js 서버 전용 코드는 분리. Blizzard 시크릿을 PC/브라우저 번들에 포함하지 않는다. 로컬 저장/SQLite는 후보, 클라우드 동기화 필수 아님. SavedVariables는 정상 종료/로그아웃/reload 등 실제 디스크 기록 시점에 읽으며 실행 중 실시간 파일 갱신을 가정하지 않는다. 파일 쓰기 중 읽기·손상·중복·이전 스냅샷·여러 캐릭터 대응 검증, Lua 파일을 실행하지 않고 제한된 데이터 파싱, 사용자 지정 디렉터리 읽기만, 외부 전송 기본 없음. 별도 유료 인프라 도입 금지.

당분간 제외: 인게임 실시간 오버레이, 자체 전투 시뮬레이션 엔진, 클라우드 심크 연산 서버, 자체 경매장 데이터 서버, 회원가입/클라우드 계정 동기화, 대규모 자동 업데이트 플랫폼, 모바일 전용 앱. 필요성·비용·보안·API/권리 검증 및 사용자 재승인 전 범위 확장 금지.

## 4. 병렬 작업의 인터페이스 및 병합 규칙
- 순서: 애드온 관측 가능성 조사/제안 → 웹이 contracts/snapshot-v1.schema.json 및 validator/CHANGELOG 정본에 필드 의미·범위·시각·상태·ID·호환성 정의 → 익명 fixture와 승인된 계약 SHA 공유 → 양쪽 독립 구현 → 별도 반례/리뷰 → 웹 정본에서 실제 생성 JSON의 parseAddon → mergeSnapshots → validate/diagnose → UI 교차 검증 → 인게임 승인 및 담당별 병합. 선행 의존이 없는 웹 분석/UI와 애드온 진단 프로토타입은 병렬 진행 가능. 신규 미합의 필드는 프로토타입 한정, 운영 export/추천 활성화 금지.
- 교차 작업의 공통 식별자(예: ADDON-004 ↔ WEB 계약/활동 작업)를 각 HANDOFF/작업 문서에 기록. 상대 담당의 요청을 작업 완료로 간주하지 않는다. 계약 변경은 기존 웹 정본만 변경하며 애드온 자체 fixture는 정본이 아니다.
- 작업 시작 시: 담당/작업 ID, 현재 양쪽 main 및 대상 브랜치 SHA, 목표, 선행 계약/의존성, 완료 조건 기록. 작업 중: 상대방에 필요한 필드/관측/검증 요청을 HANDOFF/계약 제안 문서에 명시. 완료 시: 소스 SHA, 계약 SHA, 상대 SHA, 변경 파일, 직접 테스트 명령 및 정확한 결과, 실제 게임/모의 구분, 남은 항목/차단 사유, 다음 작업을 남긴다.
- 상태는 계획/진행/독립검증완료/교차검증대기/실게임검증대기/병합완료/차단 등을 구별한다. 문서, 생성 fixture, 실제 사용자 원본 및 실제 운영 테스트를 혼동하지 않는다. 상대방 보고의 과거 SHA를 최신 main으로 오인하지 않는다.
- 정확성/예외/실패/호환성/보안 및 유지보수성 리뷰와 효율(중복 요청/연산/메모리) 리뷰를 분리. 구현 AI가 작성한 테스트 외에 별도 반례를 설계하고 결과를 확인한다. 직접 실행하지 않은 것은 PASS 금지. 실제 게임 접근/사용성 승인은 사용자 담당. 수동 CI 정책/한국어 목적별 커밋/불필요한 C드라이브 복제 금지 유지. Vercel main 자동 배포 유지. 자동으로 다른 채팅을 호출하거나 백그라운드 개발한다는 약속 금지.
